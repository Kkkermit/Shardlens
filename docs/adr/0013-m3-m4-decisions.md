# 0013. Choices made during M3 and M4

- Status: Accepted
- Date: 2026-11-13

## Context

M3 (docs, launch preparation) and M4 (scale) needed decisions the spec leaves open or that depart from its reference
choices. Embedded mode has its own record ([0012](0012-embedded-mode-on-pglite.md)).

## Decision

| Topic                | Decision                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OpenAPI              | Built by `src/openapi.ts` from the routes' own zod schemas with `z.toJSONSchema`, served at `/openapi.json`, instead of `@fastify/swagger` + `fastify-type-provider-zod`                                                                                                                | One less plugin pair to keep in step with zod 4 and Fastify 5; the document is still generated from the exact schemas the routes validate with, and a unit test checks every route and security scheme |
| Exporter instruments | Defined once in `@shardlens/core` (`EXPORTER_METRICS`, `translateEvent`); the Prometheus and OpenTelemetry packages only adapt names and units                                                                                                                                          | Both exporters report exactly the same thing; core stays dependency-free (+0.1 kB)                                                                                                                     |
| What exporters see   | Every event before sampling, with user fields blank and audit identities removed; no label is a user or server                                                                                                                                                                          | Exact counts, bounded cardinality, nothing personal in metrics systems                                                                                                                                 |
| Exporter-only mode   | `endpoint` and `apiKey` became optional; without them the client queues nothing and makes no requests                                                                                                                                                                                   | Teams with Grafana can use Shardlens without running a collector                                                                                                                                       |
| `@shardlens/http`    | Reads a structural `RawInteraction` (no runtime dependency); finds `waitUntil` among the handler's arguments; creates the client lazily                                                                                                                                                 | Works with `discord-api-types` objects and raw JSON alike; Workers forbid I/O at module scope                                                                                                          |
| Per-server rollups   | `interactions` no longer carries the server; `interactions.by_guild` keeps kind, command, outcome and server only; queries route automatically and refuse other per-server splits; migration 003 converts history                                                                       | Spec 16.2: the minute table no longer grows with commands × servers × locales                                                                                                                          |
| Funnels and cohorts  | Read raw rows, link steps by salted hash inside PostgreSQL, return counts only; journeys across salt periods count as new people                                                                                                                                                        | Privacy model unchanged: no per-person output, no cross-period linking                                                                                                                                 |
| ClickHouse           | An analytics store (preview), not a replacement: PostgreSQL stays the system of record; ClickHouse gets rows PostgreSQL accepted (so retries never double count) and answers series/top/heatmap for interactions and custom events when it covers the whole range; erasure reaches both | A complete second storage engine would duplicate every query; this delivers the heavy-query offload large bots need with a small, testable surface                                                     |
| discord.js 15        | `src/gateway.ts` feature-detects v14 (`client.ws.shards`, client shard events) and v15 (`@discordjs/ws` manager, `client.pings`, events on `client.ws`); the `/privacy` command is plain JSON                                                                                           | Public APIs only, one build for both majors; a nightly job tests `latest` and `dev`                                                                                                                    |
| Disk spool           | Core defines `EventSpool`; the adapter's `FileSpool` writes one NDJSON segment per batch (0600, 100 MB cap, oldest evicted first). Spill when memory is half full during an outage and on shutdown; replay first; delete only after 202                                                 | Spec 12/20; core stays Web-only; newest data matters most after an outage; replays are safe because ingest dedupes by ID                                                                               |
| Spool and audit mode | Audit identities are stripped before anything is written to disk; those events arrive without an identity                                                                                                                                                                               | Non-negotiable 2: raw user IDs are never stored unencrypted on the bot host                                                                                                                            |
| Load testing         | k6 against the collector image with `--cpus=1` (`tests/load`, weekly `load.yml`) with absolute thresholds                                                                                                                                                                               | Measures the spec's per-instance target directly; 5,000 events/s passed with p95 75 ms                                                                                                                 |

## Consequences

- Anyone adding a route must add it to `src/openapi.ts`; the OpenAPI unit test only checks the routes it lists.
- ClickHouse users get faster charts for new data, but every other page still depends on PostgreSQL's capacity.
- Spooled audit-mode events lose their identity; operators who need complete audit logs through long outages should
  keep the collector reachable rather than rely on the spool.
