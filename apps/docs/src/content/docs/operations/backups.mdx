Everything Shardlens stores is in its database. On PostgreSQL, back it up with `pg_dump` and keep `.env` safe
separately; on MongoDB, with `mongodump` or your host's own backups. Test a restore now and then.

## On MongoDB

Shardlens's collections all start with `shardlens_`, in the database the connection string names. If your database
already has backups (Atlas's, or your own `mongodump`), they hold Shardlens too. To back up Shardlens alone:

```sh
mongodump --uri "$MONGODB_URI" --nsInclude 'mybot.shardlens_*' --gzip --archive="shardlens-$(date +%F).gz"
```

and to restore it, with the bot stopped:

```sh
mongorestore --uri "$MONGODB_URI" --nsInclude 'mybot.shardlens_*' --drop --gzip --archive=shardlens-2026-11-24.gz
```

The dump includes `shardlens_secrets`: the app's keys and the settings key that decrypts alert and report webhooks.
Store it as you would the database itself. The audit key is never in the database: keep a copy of
`SHARDLENS_AUDIT_KEY` beside your backups if you use [audit mode](../../guides/audit-mode/).

## Daily backup on PostgreSQL

From the folder with `docker-compose.yml`:

```sh
docker compose exec -T postgres pg_dump -U shardlens -Fc shardlens > "shardlens-$(date +%F).dump"
```

Run it from cron, for example every night at 03:00:

```sh
0 3 * * * cd /opt/shardlens && docker compose exec -T postgres pg_dump -U shardlens -Fc shardlens > backups/shardlens-$(date +\%F).dump
```

Copy the dumps off the server and encrypt them; a backup holds hashed user IDs and, in audit mode, encrypted
identities.

<Aside type="caution">
  A backup without `.env` is only half a backup. Alert webhooks need `SHARDLENS_SETTINGS_KEY` and audit-mode data needs
  `SHARDLENS_AUDIT_KEY` to be readable after a restore.
</Aside>

## Restore

<Steps>

1. Stop the collector so nothing writes during the restore:

   ```sh
   docker compose stop collector
   ```

2. Restore into a clean database:

   ```sh
   docker compose exec -T postgres dropdb -U shardlens shardlens
   docker compose exec -T postgres createdb -U shardlens shardlens
   docker compose exec -T postgres pg_restore -U shardlens -d shardlens < shardlens-2026-11-13.dump
   ```

3. Start the collector with the same `.env`:

   ```sh
   docker compose start collector
   ```

</Steps>

## Test your restores

Once a month, restore the latest dump into a scratch PostgreSQL container and open the dashboard against it. A backup
you have never restored is a hope, not a backup.

## Privacy and backups

Erasure and salt destruction delete data from the live database, not from old backups. Keep backups only as long as
you need them (for example 30 days), so erased data and destroyed salts age out of them too.
