Every change comes with tests, and every bug fix with a regression test.

| Layer          | Command                                              | What it proves                                                     |
| -------------- | ---------------------------------------------------- | ------------------------------------------------------------------ |
| Unit           | `pnpm test`                                          | Hashing, normaliser, redaction, histograms, queue, schema rules    |
| Property-based | (part of `pnpm test`, with fast-check)               | The queue never exceeds capacity; redaction catches token shapes   |
| Adapter        | `pnpm --filter @shardlens/discordjs test`            | Real discord.js `Client` with raw payloads: each event is recorded, nothing throws |
| Chaos          | (part of the adapter tests)                          | Collector down, slow, `500`, `429` or killed mid-flush: the bot still answers, memory stays capped, no duplicates |
| Integration    | `pnpm --filter @shardlens/collector test:int`        | Real PostgreSQL 16 and 17 (Testcontainers): ingest, rollups, salts, retention, auth on every route |
| End to end     | `pnpm --filter @shardlens/dashboard test:e2e`        | A real collector with seeded data: every dashboard page with axe (WCAG 2.1 AA and best practices, light and dark), XSS-safe rendering, CSP, sign-in, admin gating, audit mode |
| Benchmark      | `pnpm --filter @shardlens/discordjs bench`           | SDK CPU and memory overhead against the targets                    |
| Simulated installs | `pnpm sim`                                       | The packed packages, installed with npm into three bots that coding agents set up and run against a fake Discord: exact counts, no leaked IDs, names, tokens or typed text, clean shutdown (weekly, see `tests/sim/README.md`) |
| Docs           | `pnpm --filter @shardlens/docs build`                | Code samples compile; no broken links                              |

Integration, end-to-end and simulated-install tests need Docker. Before the first end-to-end run, install the browser
with `pnpm --filter @shardlens/dashboard exec playwright install chromium`.

## One package at a time

```sh
pnpm --filter @shardlens/core test
pnpm --filter @shardlens/core test -- --watch
```

## Public API changes

The public API of each published package is tracked in an API report. After changing it on purpose:

```sh
pnpm api
```

and commit the updated report with your change.
