Bots that receive interactions over HTTP (an **Interactions Endpoint URL**) instead of the gateway use
`@shardlens/http`. It runs on Cloudflare Workers, Deno, Bun and Node (for example with `@discordjs/core`), using
Web-standard APIs only.

## Wrap your handler

  <TabItem label="Node + @discordjs/core">
    Node has no built-in server for `Request` and `Response`, so this one turns each request into a `Request`.
    `@discordjs/core` sends what comes after the first answer: follow-ups and edits.

    ```ts title="main.ts"
    import { createServer } from 'node:http';
    import { API } from '@discordjs/core/http-only';
    import { REST } from '@discordjs/rest';
    import { createBot } from './worker.ts';

    const bot = createBot(process.env);
    // Follow-ups and edits after a deferred reply: api.interactions.followUp(applicationId, token, { content })
    export const api = new API(new REST().setToken(process.env.DISCORD_TOKEN ?? ''));

    const server = createServer(async (req, res) => {
      const chunks: Buffer[] = [];
      for await (const chunk of req) chunks.push(chunk);
      const request = new Request(`http://localhost${req.url}`, {
        method: req.method ?? 'GET',
        headers: req.headers as Record<string, string>,
        body: req.method === 'POST' ? Buffer.concat(chunks) : null,
      });
      const response = await bot.fetch(request);
      res.writeHead(response.status, Object.fromEntries(response.headers));
      res.end(Buffer.from(await response.arrayBuffer()));
    });
    server.listen(8787);

    // Send what is queued before the process stops.
    process.on('SIGTERM', async () => {
      server.close();
      await bot.lens.shutdown();
      process.exit(0);
    });
    ```

    Node 22.18 and later run `main.ts` as it is (`node main.ts`); on older versions, compile it first or use `tsx`.

  </TabItem>

On Deno, Bun and Node, set `DISCORD_PUBLIC_KEY`, `SHARDLENS_URL` and `SHARDLENS_INGEST_KEY` in the environment.
Then put the bot's public URL in **Interactions Endpoint URL** in the Developer Portal. Discord checks it with a PING
and with a badly signed request, which must get a `401`: the module answers both.

<Aside type="tip">
  Any signature check works. Shardlens only needs the parsed interaction, after you have verified the request: it
  never sees the signature, the public key or the raw body.
</Aside>

## What it records

For every interaction except PING, exactly the same fields as the [discord.js adapter](../../concepts/data-collected/):
command, subcommand, options used, context, channel type, install type, locale, member tier, premium, the response type, and how long
your answer took against Discord's 3-second deadline. The user ID is hashed before anything is sent. The interaction
token and what users type never leave your bot; nor do option values, unless you list the option in
`captureOptionValues`.

- **Buttons, selects and modals** are recorded by their custom ID, with numbers and IDs replaced by `*`. Buttons and
  selects are attributed to the command that created their message, and a command that opens a modal is linked to the
  modal's submissions.
- **Errors** thrown by your handler are recorded by class (never the message) and re-thrown unchanged.
- **Slow answers**: a response returned more than 3 seconds after the interaction was created is recorded as a
  timeout, because Discord will already have shown "The application did not respond".
- **Deferred replies**: the time recorded is the time to your first answer, the deferral. Follow-ups and edits you
  send through Discord's REST API afterwards are not recorded.
- **`Response` objects**: a handler may return a `Response` instead of the body. Shardlens reads the callback type
  from a copy of a JSON body; your `Response` is returned as it is.
- **Custom events**: `lens.track(name, props, { userId, guildId }, ctx)` works as in the
  [discord.js adapter](../custom-events/). Pass `ctx` on Workers, or the event waits for the next interaction. For
  [typed events](../custom-events/#typed-events), register them with `declare module '@shardlens/http'`.

## When events are sent

- **With `waitUntil`** (Cloudflare Workers, and anything else whose handler gets an object with a `waitUntil`
  method): if any argument you pass to the wrapped handler has `waitUntil`, Shardlens hashes and sends that request's
  events through it, after your response. Nothing is left for a timer, because a Worker's timers stop with the request
  that set them. If the collector could not be reached, the next interaction asks it for its settings again.
- **Without `waitUntil`** (a long-running Node, Bun or Deno server): events are batched and sent in the background
  every 5 seconds, as in the discord.js adapter. Call `await lens.shutdown()` when the process stops.
- **Serverless without `waitUntil`**: if your platform can stop the process as soon as the response is sent and gives
  you nothing like `waitUntil`, `await lens.flush()` before you return. That adds the collector's round trip to your
  answer, so prefer `waitUntil` where there is one.

Creating the Shardlens instance is free: nothing runs (no timers, no network) until the first interaction that is
recorded, so it is safe on runtimes that forbid I/O at startup. A PING, such as Discord checking your endpoint URL,
starts nothing.

<Aside type="note">
  HTTP bots have no gateway, so there are no shard, server-lifecycle, REST or gateway metrics. Server and user installs
  can come from [webhook events](../webhook-events/) instead.
</Aside>

## Options

`createShardlensHttp` takes the options of the discord.js adapter that make sense without a gateway: `endpoint`,
`apiKey`, `mode`, `auditIncludeProfile`, `captureOptionValues`, `normaliseCustomId`, `environment`, `release`,
`optedOut`, `sampleRate`, `exporters`, `dryRun`, `logger` and `fetch`, described in
[Configuration](../../getting-started/configuration/). One is its own: `instance`, a label for this deployment in SDK health
(the Worker's name, for example). Opt-outs and erasure work the same way: `lens.optOut(userId)`,
`lens.optIn(userId)` and `await lens.forgetUser(userId)`.

A complete Worker is in
[`examples/cloudflare-worker`](https://github.com/Kkkermit/Shardlens/tree/main/examples/cloudflare-worker).
